# 设计取舍

## 搜索引擎选型（全部经 2026-10-22 实测）

| 引擎 | 结论 | 实测依据 |
|---|---|---|
| DuckDuckGo | 采用（走代理） | html 端点 POST 可用；重度使用后回 202 异常页，自动退 lite 端点兜底 |
| 百度 | 采用（直连） | 必须先 GET 首页拿 BAIDUID cookie 再搜 /s；30 秒连发 10 次会触发反爬（几分钟自愈），查询间加 0.8s 间隔 |
| Bing | 弃用 | cn.bing.com 把 /search 重定向到 www.bing.com 首页（搜索路径丢失）；www.bing.com 对无浏览器指纹的自动化请求返回与查询无关的缓存结果 |
| 搜狗／360 | 弃用 | 直连即进反爬验证页 |

双引擎的价值在限流场景实测验证：两引擎轮流被限，每次至少一个扛住，报告都能成。

## 内部 LLM 通道

- **零配置自动发现**：读 Qwen Code 的 settings.json（model.name＋modelProviders 按 id 匹配取 baseUrl＋envKey 密钥），默认复用当前激活模型，不引入任何新 API key
- 只填 `llm.model` 即切低价值辅助模型（端点密钥仍自动复用）；`enabled: false` 回到纯本地材料模式
- 两级重试链：瞬时错误（429/5xx）退避 1.5s 重试一次；合成仍失败且材料含安全类词汇时，占位替换后重试（实测所用的 OpenAI 兼容网关对「解密/破解」类词回 500——小材料/大材料均 200、仅敏感词触发；报告原始摘录不受过滤影响）
- 报告下方的原始摘录不受敏感词过滤影响，主模型仍能看到完整材料

## 降级链（每层失败都有退路）

```
LLM 查询生成失败 → 本地查询扩展
代理掉线         → 仅百度
DDG 双端点限流   → 百度扛
百度反爬         → DDG 扛
单页抓取失败     → 跳过该页
LLM 合成失败     → 本地材料报告
正文全失败       → 搜索结果摘要模式
引擎全空         → 失败报告＋建议（fetch_digest 读已知 URL）
```

## 结构性边界

- **爬虫天花板**：引擎限流是 scraping 方案的硬上限。每次 research 打约 9 个搜索请求（4～5 查询×2 引擎＋首页引导），重度使用必然撞墙；日常每天几次的使用强度实测不触发。豆包搜索（500 次/月免费）是预留的第三后端插槽
- **一次性调用不能中途调头**：方向理解偏了只能带 focus 再调研一次，或按报告缺口清单用 fetch_digest 定向补读。缺口二轮与缺口清单都是缓解，不是消除
- **deep 深度约 80 秒**：若客户端工具超时先于完成，调大 MCP_TOOL_TIMEOUT
- **时效性是软加权**：页面日期缺失时 recency 参数无法过滤该页，只能靠来源日期标注（>18 个月标「较旧来源」）供主模型判断
