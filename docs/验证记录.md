## 2026-10-26 迭代 5（LLM 通道复活＋DSH 接入）

**起因**：运行日志连续 `synthesis: false`，诊断发现 LLM 通道整体静默失败。

**根因（两个叠加）**：
1. httpx 默认 trust_env=True，本机 NO_PROXY 含 IPv6 字面量 `[::1]`，解析环境代理直接抛 `InvalidURL: Invalid port: ':1]'`——llm.py 客户端建连即崩，gen_queries 与 synthesize 全灭（复现脚本 0.1 秒内失败）
2. CTyun 网关的 glm-5.3 必思考：不带 thinking 参数回 400「thinking must be enabled」；带 thinking 后 reasoning 与正文共享 max_tokens，gen_queries 的 400 上限会把正文截到 2 字符（finish=length）

**修复**：
- 全部 httpx 客户端（llm／engines／fetch）trust_env=False，代理显式传入，行为确定
- thinking 自适应：400 且报文要求 thinking 时自动带 `thinking: {type: enabled}` 重试并记住；开启时 max_tokens 追加 4000 思考预算
- 本机 config.json 指定 deepseek-v4-flash-0731-oc 为内部合成模型（端点密钥仍自动发现；实测查询生成 2.2 秒、合成稳定在预算内）

**顺带修复**：
- fetch_digest 不带 question 返回空报告（digest 复用了 research 的零命中剔除，检索词为空时全剔除）——select_sources 加 filter_noise 参数，digest 模式不剔除零命中与同域名来源
- 代理离线时 DDG 仍直连白等 15 秒超时——现在直接跳过
- 缺口补搜结果未并入总结果（报告「其他候选」看不到补搜 URL）——并入并回写缓存，同题二跑免补搜
- 报告缺口分析未计入 focus 词；运行日志不记 LLM 失败原因（现在记 llm 与 synthesis_error 字段）

**验证**：
- 32 项单测全过（新增 thinking 自适应重试、digest 零命中保留 2 项）
- 实网冒烟：standard 36 秒全链路，LLM 查询扩展＋合成报告均成功（日志 llm: true, synthesis: true）；quick 37 秒，百度反爬时 DDG 扛住（24 条）
- fetch_digest 无 question 实测：2 URL 4 秒返回 1533 字摘要（修复前为空报告）
- MCP stdio 冒烟：initialize 743ms，research 实调出报告
- DSH 接入：dsh-bundle 经 npm pack＋file: 安装（Windows 符号链接权限绕行），DSH 会话内 mcp__oneresearch__research 实调 45 秒出合成报告（trafilatura 2.3.1／2026-10-06 等事实可核对）
