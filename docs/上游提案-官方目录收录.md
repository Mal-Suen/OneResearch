## English draft

**Title:** Proposal: add `oneresearch-dsh-bundle` to the official catalog

**Body:**

Hi maintainers,

I'd like to propose adding a third-party bundle to the official catalog: `oneresearch-dsh-bundle`.

**What it is.** A configuration-only bundle that connects OneResearch, an open-source research MCP server (GPL-3.0-or-later, github.com/Mal-Suen/OneResearch). It exposes two tools:

- `research` — one-call web research: dual-engine search (DuckDuckGo + Baidu), concurrent fetching, extraction, relevance ranking, and optional LLM synthesis, returning a ready-to-answer report with per-source excerpts and a coverage-gap list.
- `fetch_digest` — batch-fetch up to 10 known URLs and return condensed excerpts.

**Why it may fit the catalog.**

- Zero new API keys: the optional internal LLM channel reuses the host agent's existing model config (e.g., Qwen Code settings.json); without it, the pipeline degrades to a local-materials report. This makes it install-and-go for coding-plan users.
- Chinese + English: Baidu runs direct-connect (no proxy) alongside DuckDuckGo, which is unusual among research MCPs and useful for users in China.
- It targets the per-tool-call billing model: one `research` call replaces the 15-30 search/read round trips an agent would otherwise make.
- Already distributed through a custom plugin-market index (format 1) and installable via the standard `dsh-mcp-client` stdio transport; `engines.dsh: >=0.2.1-rc.2`.

**Install target** (from our market index):

```
git+https://github.com/Mal-Suen/OneResearch.git#<commit>&path:/dsh-bundle
```

Prerequisite on the user side: `pip install oneresearch` (or `pip install git+https://github.com/Mal-Suen/OneResearch.git`; PyPI release pending).

**Maintenance.** I'm the author and maintain it actively (32 unit tests, smoke tests, documented verification log). Happy to keep the `engines.dsh` range accurate and respond to catalog requirements.

If third-party bundles are out of scope for the official catalog, feel free to close — the custom-market route already works well. Thanks for the great harness either way.
